# Phase 2 implementation coverage matrix — data preparation and pilot inputs

**Scope.** This is an implementation plan for audited raw records through reproducible directed arcs, cores, and panel inputs. It deliberately excludes ERGM fitting, simulation, scoring, and final experiment execution. It reconciles the agreed plan with `configs/defaults.yaml`, the audit sheets, and the implemented data drivers.

## Fixed cross-dataset output contract

All derived records must carry `dataset_id`, source version/checksum, deterministic build configuration, and a manifest hash. Raw files remain unchanged and untracked.

| View | Minimum deterministic contract |
|---|---|
| `native_events` | `event_id`, `sent_at`/phase (if available), ordered canonical `tail_nodes`, ordered canonical `head_nodes`, and raw provenance. Require non-empty, disjoint tail/head; preserve an explicit event-construction label (`recorded`, `reconstructed`, or `none`). |
| `directed_arcs` | One `tail, head` row per retained directed dyad, with `interaction_count` and binary `present = interaction_count >= 1`; remove self-loops. This implements defaults: `dichotomize_rule: at_least_one_interaction` and `remove_self_loops: true`. |
| `core_100` | Ordered node table and induced binary/weighted arc table. Rank by a **predeclared** sent-plus-received activity statistic, then stable canonical node ID to break ties; record the ranking reference period. Datasets with fewer than 100 nodes emit all nodes and an explicit `core_size_exception`, not padded nodes. |
| `panels` | `panel_index` plus one binary arc table per window, built from events/rows in that window only; include an explicit fixed node set, window origin/end, aggregation rule, and empty-window handling. For chronological evaluation, any active-node candidate universe is built using history through origin `t` only. |
| `input_manifest` | Raw checksum/count, schema checks, exclusions by reason, policies/parameters, node ordering, core rule, panel rule, and target eligibility. This is the pilot gate artifact, not an after-the-fact narrative. |

**Common promotion gates.** A dataset cannot enter a target until its provenance sheet has source/version/checksum/license, raw unit, direction semantics, event identifier/bundle evidence, deduplication rule, time span, and restrictions (audit `README.md`). Every view must pass schema/count reconciliation, no-loop validation, deterministic sort/order validation, and an explicit same-node-set manifest. Before scaling, enumerate capped formal concepts on each analysis core and inspect arity, overlap, aggregation ratio, and whether the footprint-free stress split leaves enough concepts. The config fixes seed `20261013`, nominal core size `100`, and main masking defaults, but it does **not** resolve the research choices listed below.

## Implementation coverage and sequencing

1. **Do not treat an audit as a prepared input.** Scripts `01`–`14` establish Enron provenance and its timestamp distribution. The approved strict map policy is materialized by `15_materialize_enron_strict_mapping.py`; then `25_build_enron_custodian_projection.py` constructs the custodian-node core-100 and calendar panels. The local result must still pass its count, core-size, and panel checks before Enron is pilot-ready. The other source adapters preserve their plan-defined gates.
2. The repository now uses a compact registry (`configs/datasets.yaml`), an eligibility/status checker (`scripts/20_phase2_status.py`), dataset-specific adapters (`scripts/21`–`25`), and a skip-safe batch runner (`scripts/26_run_phase2.py`). The next computational phase should add shared concept, masking, score, and R-interchange modules rather than duplicating source parsing.
3. Run each source-specific audit gate first; only then materialize the common views. Materialize `core_100` from the **same declared source view** used for each static comparison. For chronological inputs, preserve a separate origin-safe selection/candidate manifest rather than leaking post-origin activity.
4. `scripts/28_audit_formal_concepts.py` supplies the first representation-gate driver: a deterministic cap-first directed formal-concept audit with concept/arity, role-overlap, capped-footprint-coverage, and arc-multiplicity outputs. The fixed `phase2-eu-core-concepts` target runs the `(|T|,|H|) ≤ (3,3)` screening audit. Larger cap sensitivities remain explicit pilot decisions rather than unbounded enumeration.
5. Pilot input completion means: all required manifests exist; eligible targets are explicitly labelled; capped concept enumeration has passed on the selected cores; the footprint-free split has adequate retained concepts; and chronology has only the plan-eligible Enron/EU-core inputs (CAVIAR phases descriptive only).

## Material research choices that must remain explicit parameters or gates

| Choice | Required treatment |
|---|---|
| **Node identity and core activity** | Freeze identity/alias rules and define “sent + received activity” (recommended: retained interaction occurrences, with stable node-ID tie break). Record whether the rank is full-observation, training-only, or per-origin; do not use full-period ranks in an origin-safe forecast without labelling the leakage risk. |
| **Email deduplication and recipient policy** | Enron needs an explicit message-copy/quoted-copy/retransmission rule despite no raw-SHA/Message-ID duplicates in the present audit; Jmail needs cross-release duplication. Keep source IDs. Enron Bcc is resolved as a duplicate Cc artifact; Jmail To/Cc/Bcc remains a policy gate. |
| **Enron projection** | The agreed plan says custodian mailboxes are nodes, whereas the provenance events use 86,408 email-address nodes. The strict policy is now frozen: approve only unique rank-one, at-least-90%-support, non-colliding mappings; exclude a whole event with an unmapped participant; retain 1998–2002 UTC. The local projection result still must establish adequate retained events and a core-100. |
| **Direction and valued matrix coding** | CAVIAR caller → receiver is approved only for the unique-labelled full static matrix; its phase series is excluded because of the unresolvable CAVIAR7 duplicate label. Ciel direction remains unconfirmed. Positive/zero/missing semantics, self-ties, representation reconciliation, and any valued sensitivity must be documented—not assumed. |
| **Time construction** | Enron: calendar months after the inclusive UTC interval 1998-01-01 through 2002-12-31. EU-core: anchored 30-day windows, with 14/28-day sensitivity. CAVIAR: ordered phases only/descriptive. Jmail/MathOverflow: no chronology until decisions settle. MathOverflow’s answer window is a substantive reconstruction parameter. |
| **Native-event status** | EU-core/CAVIAR/Ciel have no primary native events. MathOverflow events are reconstructed. Do not upgrade timestamp coincidence, a matrix phase, or an aggregate dyad to a recorded event. |
| **Hyperarc caps and pilot representation check** | The plan sets `k_T,k_H` from the 95th percentile of native event sizes or concept sizes, sensitivity `{3,5,8}`; config presently leaves both caps `null`. Freeze caps before enumeration and record selected/eligible counts and overlap. |
| **Panel/candidate isolation** | A panel tie means at least one interaction *in that window*, not a standing relation. Store weights for supplementary use, but primary ties are binary. Candidate nodes active through `t` and all negative-panel construction must be derived without later windows. |
